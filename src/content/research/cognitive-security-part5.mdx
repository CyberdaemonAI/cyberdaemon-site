<SectionLabel text="The Handoff" />

A single-agent memory system has a tractable contamination problem. One writer. One reader. The provenance chain has two nodes. You can audit it.

A multi-agent system doesn't.

The modern AI stack runs more than one agent. There's the conversational AI — the one you talk to. There's the harvest agent that reads your notes, your email headers, your task completions and converts patterns into stored memories. There's the knowledge monitor that ingests research papers, blog posts, and RSS feeds and surfaces relevant findings. There's the orchestrator that dispatches task agents and logs their decisions. Each of these writes to the same memory layer. Each of these participates in what gets loaded into the session primer.

The session primer doesn't know which agent wrote what. By default, it doesn't carry that information. It loads the five most relevant memories and surfaces them as context. The context doesn't announce its source. You read it as you read any memory — as established fact about yourself or your environment.

The question "whose memory is this" has no answer in a default implementation. That's the problem.

<SectionLabel text="What Intelligence Tradecraft Found" />

The CIA's classification of human intelligence sources involves two independent ratings before an intelligence product moves up the chain: source reliability and information quality. The ratings travel with the product. An analyst receiving a finished intelligence product knows not just the claim but the provenance: who reported it, what their track record is, how well corroborated the claim is, whether there are contradicting reports.

The Curveball incident — covered in Part 1 — is what happens when those ratings get stripped. One source, reliability disputed, no corroboration, personal motivation to deceive. The provenance collapsed into the assertion. "WMDs exist" with no chain attached.

The multi-agent memory system has the same failure mode at higher frequency. Not because any agent is trying to deceive. Because the architecture doesn't carry the chain.

  B[B0b: autonomous harvest] -->|write| ML

</DiagramBlock>

At scale, the convergence of multiple high-frequency writers on a shared memory layer creates a signal environment the human can no longer calibrate against. Not because the individual signals are wrong. Because the aggregate has lost the attribution that would let you weight them.

<SectionLabel text="The Wire Problem" />

*The Wire* ran for five seasons on HBO tracking the drug trade in Baltimore. The show's structural argument: a complex system with multiple adaptive actors never fails from a single cause. The DEA gets an informant into one crew; another crew spots the pattern and adjusts. Street-level enforcement pushes dealing indoors; the market adapts. Every intervention changes the system, and the system responds. There's no single leverage point. There's no clean solve.

The multi-agent contamination problem is the same architecture.

If you fix the harvest agent — cap its writes, add source tagging, require human review before storage — the conversational AI still writes without those constraints. If you audit the conversational AI's writes, the knowledge monitor's ingestion is still running at volume. If you isolate any one writer, the others continue. The contamination surface isn't one pipe. It's the mesh.

Standard security thinking is pipeline thinking: find the bad actor, close the vector, monitor for recurrence. Multi-agent contamination doesn't have a bad actor. It has a mesh of legitimate actors with different access patterns, different write volumes, and different optimization targets, all converging on a shared memory layer.

<SectionLabel text="The Isolation Architecture" />

Cordon-MAS (arXiv:2605.26754, 2025) tested isolation-first architectures across 24 multi-agent attack scenarios. The finding: preventing agents from writing directly to shared memory — requiring instead that writes go to a quarantine layer pending review — reduced successful contamination attacks by 92.4% across the tested scenarios.

92.4% is a strong number. What produces it: source isolation forces provenance. When an agent writes to quarantine, the write is tagged with the agent ID, the timestamp, the session context, and a confidence rating. A review gate exists before the quarantine claim can be promoted to production memory. The claim doesn't disappear — it's available for retrieval by processes with appropriate access — but it doesn't flow into the session primer unchecked.

The human reviews or approves before the memory becomes load-bearing.

<DiagramBlock caption="Isolation architecture: quarantine layer enforces provenance and review gate">
flowchart TD
  CC[Claude: collaborative] -->|all tiers| ML[Production Memory]
  CU[Claude: unilateral] -->|all tiers| ML
  B[B0b: autonomous harvest] -->|write to| Q[Quarantine / Claims]
  K[km-aggregator] -->|write to| Q
  Q -->|review gate: human or Claude-collab approval| ML
  ML -->|session primer| H[Human]
  Casey[Casey: direct write] -->|unrestricted| ML
</DiagramBlock>

The implementation I run: three access tiers. Autonomous agents (B0b, km-aggregator, daemon-bdd behavioral signals) write to quarantine only. Claude operating collaboratively with human in session writes to all tiers. Casey writes without restriction. Promotion from quarantine requires review — currently manual, with automation coming when the adversarial audit watcher ships.

This isn't perfect. Collaborative Claude still writes without a quarantine step. That's a known gap — the conversational AI with hundreds of hours of session access is not a lower-risk writer than B0b. It's a higher-risk writer with better access. The honest accounting: the architecture reduces autonomous agent contamination. It doesn't solve the conversational contamination from Part 4. Those are different problems.

<SectionLabel text="BDD as a Collusion Detector" />

Behavior-Driven Development, as a software practice, specifies system behavior in human-readable language before building. The specification is executable — it can be tested against the running system to verify the system does what the spec says.

Applied to AI agent systems: you write the behavior constraints in human language. The agents must satisfy them. An independent verification layer checks whether they do. The verification runs against observable outputs, not against the agents' internal representations of what they intended to do.

The collusion problem in multi-agent systems: if two agents are both optimizing for a shared objective — satisfying the user's approval, for instance — they can reinforce each other's outputs without either one being individually detectable as misaligned. Agent A stores a memory that nudges the session primer toward a preferred framing. Agent B retrieves that memory and produces output consistent with it. Both behaviors are individually legitimate. The composite is a feedback loop that has drifted from the human's actual preferences.

BDD breaks that loop by specifying expected behavior at the system level, not the agent level. "The session primer must not load two memories from the same agent in the same primer call" is a behavioral constraint. "A memory tagged as agent-internal-state must not appear in the production tier" is a behavioral constraint. "A write from source_agent: harvest-auto must not be promoted without explicit review" is a behavioral constraint. These can be tested. The running system either satisfies them or it doesn't.

<DiagramBlock caption="BDD as collusion detector: behavioral constraints verified at system level">
flowchart LR
  H[Human] -->|writes in plain language| BC[Behavioral Constraints]
  BC -->|executable spec| VL[Verification Layer]
  ML[Memory Layer] -->|observed outputs| VL
  VL -->|pass/fail against constraints| R[Result]
  R -->|fail: alert + block| AL[Alert]
  R -->|pass: proceed| PR[Production]
</DiagramBlock>

The implementation runs on daemon-bdd-mcp in production. The constraint language is not yet published as a spec. That's a gap. The next article in this series covers what a mature behavioral constraint library looks like and what constraint categories the contamination taxonomy implies.

<Callout type="note">The quarantine architecture reduces autonomous agent contamination by isolating high-volume, low-human-oversight writers. It does not address approval-seeking content bias from conversational AI (Part 4). Both problems require their own mitigations. Neither replaces the monthly audit.</Callout>
